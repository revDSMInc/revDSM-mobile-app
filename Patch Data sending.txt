What the mobile app actually sends (src/utils/installer-step-data.ts +
InstallerService.updateJob):

  leaving any of the 7 steps →  { "stepData": { …that step's keys… } }
  "Job Completed?" → Yes      →  { "status": "completed",
                                   "stepData": { …ALL 7 steps merged… } }

Each step PATCHes on the way out so a second installer signing in sees what
has already been done. Photo arrays are always sent as the step's CURRENT
full set (never an increment) — the multipart upload appended each shot, and
restating the set is what clears a retaken or deleted photo. A photo joins
its array only once its upload returned an s3url.

Not sent: nothing for Step 6 · CoC (no backend field exists), and no
"had material on truck" flag for Step 1 (no backend field either — only
Return has `materialReturnNothingToReturn`).
